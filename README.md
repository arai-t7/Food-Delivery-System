# food CRM

Приложение для заказа и доставки еды. Клиент выбирает блюда, оформляет заказ и отслеживает его статус. Администратор видит очередь заказов, кухня отмечает этапы приготовления, курьер отмечает этапы доставки.

## Быстрый запуск

Понадобятся Python 3.12, Node.js 22.12+ и npm. Запустите команды из корня проекта в двух отдельных терминалах. Для локальной работы используется SQLite, поэтому отдельный сервер базы данных не нужен.

### 1. Сервер API

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
cd backend
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

В Windows создайте окружение командой `py -3.12 -m venv .venv` и активируйте его в PowerShell через `.\.venv\Scripts\Activate.ps1`. Остальные команды те же.

При первом запуске сервер создаёт `backend/food_crm.db`, таблицы, начальное меню и демо-учётки сотрудников. Проверка работы API доступна на [127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health), интерактивная документация Swagger — на [127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

### 2. Веб-интерфейс

```bash
cd frontend
npm ci
npm run dev
```

Откройте [127.0.0.1:5173](http://127.0.0.1:5173). Vite направляет запросы `/api` на сервер на порту 8000. Во время работы оба терминала должны оставаться запущенными. Для остановки нажмите Ctrl+C в каждом из них. При повторном запуске достаточно активировать окружение и запустить Uvicorn и Vite.

## Как проверить заказ целиком

1. Зарегистрируйте клиента, например с адресом `client@example.com`. Адрес служит логином, подтверждение по почте не требуется.
2. Добавьте блюдо из меню в корзину, укажите адрес доставки и оформите заказ. Статус виден в разделе «Заказы».
3. В другом профиле браузера или после выхода из клиентской учётки войдите как сотрудник кухни. Возьмите заказ в работу и отметьте его готовым.
4. Войдите как курьер, отметьте, что заказ в пути, а затем доставлен.
5. Проверьте итоговый статус в истории клиента. Администратор может просматривать общую очередь и менять статусы через свой экран.

Пароль всех демо-сотрудников — `food-crm-demo`. Адреса на `example.com` служат заглушками.

| Роль | Почта | Экран |
| --- | --- | --- |
| Администратор | `admin@example.com` | `/desk` |
| Кухня | `kitchen@example.com` | `/kitchen` |
| Курьер | `courier@example.com` | `/route` |

## Настройки и данные

Локально можно запуститься с настройками по умолчанию. Чтобы задать свои значения, скопируйте `backend/.env.example` в `backend/.env` и перезапустите API.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | По умолчанию используется файл SQLite `backend/food_crm.db`. Для PostgreSQL укажите строку подключения к уже созданной базе, например `postgresql://USER:PASSWORD@HOST:5432/food_crm`. |
| `JWT_SECRET` | Секрет подписи токенов входа. Для развёртывания задайте уникальное значение. Смена секрета завершает активные сеансы. |
| `JWT_EXPIRE_DAYS` | Срок действия токена в днях, по умолчанию 7. |
| `SEED_DEMO` | Разрешает создание демо-сотрудников при запуске, если в базе ещё нет сотрудников. Для развёртывания задайте `false`. Уже созданные учётки сохраняются. |
| `CORS_ORIGINS` | Разрешённые адреса веб-интерфейса через запятую, включая протокол и порт. Нужны, если браузер обращается к API с другого адреса. |

Если используете SQLite из предыдущей версии, остановите API и сделайте резервную копию. Переименуйте файл базы в `food_crm.db` или укажите его путь в `DATABASE_URL`. Существующие учётки и заказы сохранятся, а их реквизиты и номера останутся такими, какими записаны в этой базе. Для демо с новыми учётками запустите API с отдельной пустой базой.

## Что находится в проекте

| Путь | Назначение |
| --- | --- |
| `backend/app/main.py` | Создаёт приложение FastAPI, подключает маршруты и инициализирует базу при запуске. |
| `backend/app/config.py`, `database.py`, `models.py` | Загружают настройки, настраивают соединение с базой и описывают таблицы. |
| `backend/app/routers/` | Обрабатывает регистрацию и вход (`/api/auth`), меню (`/api/menu`), корзину (`/api/cart`) и заказы (`/api/orders`). |
| `backend/app/security.py`, `deps.py` | Хешируют пароли, проверяют токены и ограничивают доступ по ролям. |
| `backend/app/seed.py` | Заполняет начальное меню и создаёт демо-учётки. |
| `frontend/src/App.jsx` | Экраны входа, меню, корзины, истории и очередей сотрудников. |
| `frontend/src/api.js` | Запросы к API, хранение токена входа и общие подписи для интерфейса. |
| `frontend/vite.config.js` | Настройка React и прокси к API для локальной разработки. |

## Проверка и сборка интерфейса

Из папки `frontend` выполните `npm run lint` для проверки кода и `npm run build` для сборки в `frontend/dist`. Команда `npm run preview` позволяет просмотреть сборку локально при запущенном API.

При развёртывании отдавайте файлы из `frontend/dist`, направляйте запросы `/api` на FastAPI и возвращайте `index.html` для клиентских маршрутов вроде `/orders` и `/kitchen`. Интерфейс обращается к API по относительным путям, поэтому браузер должен видеть оба сервиса через один адрес.
